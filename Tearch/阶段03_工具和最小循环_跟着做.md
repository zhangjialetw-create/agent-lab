## 第 9 节：给工具固定输入和输出

在项目根目录新建 `paths.py`：

```python
from pathlib import Path

# __file__ 是这个 Python 文件的位置；不受终端当前目录影响。
ROOT = Path(__file__).resolve().parent
DATA = ROOT / "data"
NOTES = ROOT / "notes"
RUNS = ROOT / "runs"
```

后续代码共同从这个文件取路径，避免每个文件各写一个不同的长路径。

新建 `tools.py`：

```python
import json
from paths import DATA


def study_stats(query=""):
    # 参数 query 留给统一接口使用；数据路径固定，模型不能指定任意文件。
    records = json.loads((DATA / "sessions.json").read_text(encoding="utf-8-sig"))
    if not isinstance(records, list):
        raise ValueError("学习记录必须是列表")
    total = 0
    for record in records:
        if not isinstance(record, dict):
            raise ValueError("每条记录必须是字典")
        minutes = record.get("minutes")
        if type(minutes) is not int or minutes < 0:
            raise ValueError("minutes 必须是非负整数")
        total += minutes
    count = len(records)
    return {
        "count": count,
        "total": total,
        "average": total / count if count else 0.0,
        "source": "sessions.json",
    }


def search_notes(query):
    from knowledge import search
    if not isinstance(query, str) or not query.strip():
        raise ValueError("搜索词不能为空")
    return search(query)


TOOLS = {"study_stats": study_stats, "search_notes": search_notes}


def execute(name, query):
    if name not in TOOLS:
        raise ValueError(f"未允许的工具：{name}")
    return TOOLS[name](query)


if __name__ == "__main__":
    print(study_stats())
```

先只运行统计工具：

```powershell
.\.venv\Scripts\python.exe tools.py
```

预期：`count` 为 3，`total` 为 75，`average` 为 25.0，`source` 为 sessions.json。如果阶段 02 改了数据，按你的文件重新计算预期。

从已有知识读新代码：

1. `study_stats` 接受一个默认空的 query，为以后统一工具调用预留参数。
2. 数据文件由程序固定，不接受模型随意给出的文件路径。
3. `isinstance(records, list)` 检查是否为列表；`record.get("minutes")` 取字段，缺少字段时返回 None。
4. `type(minutes) is not int` 拒绝文字、空值、布尔值；检查 `< 0` 拒绝负分钟。
5. `raise ValueError(...)` 主动告诉调用者输入不合要求。
6. `total / count if count else 0.0` 是前面 if/else 的简写：count 非零才除。
7. `source` 保存来源，后续可用来引用。

`search_notes` 会到下一阶段才用，`from knowledge import search` 放在函数内部，因此现在只运行统计不需要 knowledge.py。

小练习：把一条记录的 minutes 改成 `-10`。运行会得到明确错误。恢复 25 后再运行成功。

## 第 10 节：工具白名单，数据不是代码

`TOOLS` 的键是工具名称，值是 Python 函数。`TOOLS[name](query)` 分两步理解：先取到函数，再传参数调用。

新建根目录文件 `tool_demo.py`：

```python
from tools import execute

print(execute("study_stats", "统计总分钟"))
try:
    execute("powershell", "任意命令")
except ValueError as error:
    print("已拒绝：", error)
```

```powershell
.\.venv\Scripts\python.exe tool_demo.py
```

预期先显示统计结果，然后显示“已拒绝：未允许的工具：powershell”。

`try` 包住可能失败的操作；`except ValueError` 只处理这一类错误；`as error` 把错误对象交给变量。我们的程序选择记录并解释错误。

模型将来输出 `"study_stats"` 只是一个字符串。真正执行哪个函数，由你写的工具表决定。这里没有 `eval`、`exec` 或任意 shell 工具。

小练习：把工具名写成 `"study_stat"`，观察一样会被拒绝。一个字母不同就是不同的键。

## 第 11 节：把一次动作变成“决定 → 执行 → 观察 → 结束”

在 basics 中新建 `05_loop.py`：

```python
# 假模型用于观察流程，不含大语言模型。
actions = [
    {"action": "add", "a": 25, "b": 35},
    {"action": "finish"},
]
history = []
for step, decision in enumerate(actions, start=1):
    print("第", step, "步：", decision["action"])
    if decision["action"] == "finish":
        print("结束，历史结果：", history)
        break
    if decision["action"] == "add":
        result = decision["a"] + decision["b"]
        history.append(result)
        print("工具返回：", result)
```

```powershell
.\.venv\Scripts\python.exe basics/05_loop.py
```

预期：

```text
第 1 步： add
工具返回： 60
第 2 步： finish
结束，历史结果： [60]
```

逐段解释：

- `actions` 暂时代替模型，给出事先写好的两次决定。
- `enumerate(actions, start=1)` 同时给你序号和内容。
- `history = []` 保存已经执行的结果；`append` 追加一项。
- `break` 立刻结束循环。
- `"action"` 告诉框架应该做什么；`"a"`、`"b"` 是工具的参数。

这是模拟决策流程，还没有语言模型。它的价值是：如果后面接模型失败，你可以保留同一个执行框架，用假模型检查到底哪一部分坏了。

小练习：在 finish 之前加一条 `{"action": "add", "a": 10, "b": 20}`。历史应变成 `[60, 30]`。再把 finish 移到最前面，验证后面的加法不会执行。

验收：不用“AI 自动理解了”来解释结果，明确说出列表、字典、循环、判断分别做了什么。
